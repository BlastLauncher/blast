## Goal

Form commands render and submit headlessly: `Form`, `Form.TextField`,
`Form.TextArea`, `Form.Dropdown` (+ `.Item`, `.Section`), `Form.Checkbox`,
`Form.DatePicker`, `Form.Description`, `Form.Separator`, and
`Action.SubmitForm` (top usage: Form 1,362 extensions, SubmitForm 1,267,
TextField 1,102, Dropdown 799, Description 765, TextArea 678).

## Context

- Check every prop in `compat/raycast-api/index.d.ts`.
- Values live in the runtime: controlled fields (`value` + `onChange`) and
  uncontrolled ones (`defaultValue`, tracked by `id`). Clients change a field
  by dispatching its `onChange` handler with the new value (add a runtime-side
  handler even for uncontrolled fields so clients can always edit).
  `Action.SubmitForm.onSubmit` receives `{ [id]: value }` for all fields.
- Field `error`, `info`, `onBlur`/`onFocus`, `storeValue` (partial unless
  persisted via the 0021 storage capability — use it if straightforward),
  `autoFocus`, `enableMarkdown` pass through. Date values cross the wire as
  ISO strings (serializer already supports `Date`); `DatePicker.Type` values
  from the declarations.
- `Form.Props.actions` → existing `Slot` convention. `Form.ItemReference`,
  `useForm` (that's `@raycast/utils`), FilePicker, TagPicker are out of
  scope here — leave them stubbed.
- CLI: script command `field <id> <value>` (dispatch onChange; booleans for
  checkboxes as `true`/`false`) and `submit` (run the SubmitForm action);
  document in `--help` and `docs/architecture.md`.
- `@covers`, `bun run compat:report`, `bun run corpus:smoke` (stay 13/13),
  commit reports after `bun run fmt`.
