## Goal

The browser demo launches each command in the mode its manifest declares. A
`no-view` command runs to completion and reports back; a `menu-bar` command
shows its `MenuBarExtra` as a navigable menu. Today both show a blank screen.

## Context

- `examples/browser-demo/client.ts` sends `init` with `mode: "view"` for every
  command (search `mode: "view"`). Of the 74 sweep `empty` commands, 53 are
  `no-view` (39 of them `rectangle/*`) and 8 are `menu-bar`.
- The runtime already handles all modes (`packages/runtime/src/core.ts`: a
  `no-view` command awaits `default(props)` then exits). The browser runtime
  posts `{ type: "exit", code }` on the port (`packages/runtime/src/browser.ts`);
  `handleRuntime` in client.ts ignores it.
- client-core already models menus: `ViewKind` `"menu-bar"`,
  `packages/client-core/src/menu-bar.ts` (`menuBarView`, actions move,
  activate, back). The TUI is the reference client: `packages/tui/src/app.tsx`
  (no-view quits once its HUD is gone) and `packages/tui/src/menu-bar.tsx`.
- Mode source: for prebuilt catalog commands, `CatalogManifest`
  (`examples/browser-demo/bundles.ts`, filled in `prebuild.ts`) has no mode
  yet; add one per command and validate it. Commands loaded from source read
  `commands[].mode` from `package.json`. Missing or unknown means `view`.
- Expect some `no-view` commands to move from `empty` to a `runtime-error` or
  `capability-denied` outcome (e.g. ones that call `getApplications`). That is
  the honest result; do not stub macOS apps.

## Acceptance

- [x] `init` carries the declared mode for both catalog and source launches;
      unit tests cover the manifest mode parsing and the `view` default.
- [x] `no-view`: on `exit` with code 0 the demo returns to the root list and
      shows the command's last HUD or toast title in `#status`, or
      `<Command title> finished` when there was none. A non-zero exit keeps
      the error state. Keystrokes buffered by 0137 are dropped, not replayed.
- [x] `menu-bar`: `render.js` draws the menu (title, sections, items with
      icons/subtitles, submenus). ↑/↓ move, Enter/→ activate or open a
      submenu, ←/Esc go back, Esc at the top returns to root, and clicking an
      item activates it. `render.test.js` covers the markup.
- [x] A fixture under `fixtures/extensions/` (new, do not edit shared ones)
      with a `no-view` command that calls `showHUD` and a `menu-bar` command
      with a submenu; `bun run site:e2e` asserts both flows and passes three
      runs in a row.
- [x] The sweep classifies a `no-view` command that exits 0 as `completed`
      and a menu with items as `rendered`; `browser-sweep.test.ts` covers
      both. `compat/BROWSER-SWEEP.md` / `browser-sweep.json` regenerated by
      `bun run site:sweep:browser`; Handoff lists the new totals.
- [x] `bun run verify` passes.

## Out of scope

- Making `rectangle` or other macOS-app commands work in a browser.
- Menu-bar background refresh (`interval`), `LaunchType.Background`, or a
  persistent menu-bar strip; the menu shows only while the command is open.
- `macOS` or TUI clients.
